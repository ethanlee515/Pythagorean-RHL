\subsection{Games and invariant}

Let \(C_{\cA}^{\mathsf{open}}\) be the IND-CPAD experiment with calls to its
oracle interface left unresolved.
Let \(P_{\mathsf{real}}\) implement the
real encryption, evaluation, and flooded-decryption oracles, and let
\(P_{\mathsf{sim}}\) differ only by flooding around the table plaintext on decryption queries.
Denote by \(P_s\) the code for answering the first $q$ decrypt calls,
and \(P_r\) for the remaining calls.
We write
\[
 G(P_s,P_r)=
 \mathsf{Link}\bigl(
  \mathsf{compile}_{q}(P_s,\mathsf{ODec},C_{\cA}^{\mathsf{open}}),P_r
 \bigr).
\]
where $\mathsf{compile}_{q}$ ``factors out" the first \(q\) calls to the oracle
\(\mathsf{ODec}\), without assuming that $C_{\cA}^{\mathsf{open}}$ has a fixed query
schedule.

The proof maintains an invariant \(\Phi\) over challenger state.
It records
initialized, good keys; agreement of public data and the challenge bit; table
validity under encryption and evaluation; and the decryption query counter.
In
particular, each supported table row \((m_0,m_1,c)\), viewed on the selected
branch \(b\), satisfies
\[
 d(\mathsf{dec}_0(sk,c),m_b)\leq e_c.
\]
Initialization establishes \(\Phi\), and encryption/evaluation preserve it.
The selected decrypt prefix preserves it as well, while incrementing the counter.

\subsection{Hybrid chain}

We define the following sequence of hybrid games:
\begin{align*}
 H_0 &= \mathsf{IND\text{-}CPAD}_{\mathsf{NF}[S],q}(\cA),\\
 H_1 &= \mathsf{Link}(C_{\cA}^{\mathsf{open}},P_{\mathsf{real}}),\\
 H_2 &= G(P_{\mathsf{real}},P_{\mathsf{real}}),\\
 H_3 &= G(P_{\mathsf{sim}},P_{\mathsf{real}}),\\
 H_4 &= G(P_{\mathsf{sim}},P_{\mathsf{sim}}),\\
 H_5 &= \mathsf{Link}(C_{\cA}^{\mathsf{open}},P_{\mathsf{sim}}),\\
 H_6 &= \mathsf{IND\text{-}CPA}_{S}(\cB_{\cA,q}).
\end{align*}
We verify the chain of hybrids
\begin{equation}
\label{eq:hybrid-chain}
 H_0\xrightarrow{0}H_1\xrightarrow{0}H_2
 \xrightarrow{\sqrt{q\epsilon_{\mathsf{nf}}/2}}H_3
 \xrightarrow{0}H_4\xrightarrow{0}H_5\xrightarrow{0}H_6.
\end{equation}
The labels are statistical-distance bounds.
The zero-cost steps have distinct roles:
\begin{itemize}
\item \(H_0=H_1\) unfolds package linking.
\item \(H_1=H_2\) is same-package compiler correctness: exposing selected
calls and answering them with the package they originally called preserves
semantics.
\item \(H_3=H_4\) changes the residual decrypt $P_r$ implementation.
After \(q\) selected decrypt entries, the shared counter makes every $P_r$ call
assert fail on both sides.
\item \(H_4=H_5\) removes the compiler after selected and residual calls use
the same simulated package.
\item \(H_5=H_6\) unfolds package linking again, connecting the experiment back to the IND-CPA game.
\end{itemize}
Each game hop is formalized as a theorem over SSProve semantics.

\label{sec:paid-hop}

The selected decrypt body factors into a deterministic prefix, one Gaussian
sample, and deterministic postprocessing.

On valid oracle inputs, \(\Phi\) gives \(d(a,m)\leq e\).

The zero entries in the tuple certify that shared prefix and postprocessing add no KL cost.
On the other hand, the assertion-failing case places the same mass at \(\bot\).

The trace-compiler replacement theorem applies \Cref{lem:one-call} to the
first \(q\) selected calls, preserving dependencies between queries.
It
accumulates a conditional KL budget \(q\epsilon_{\mathsf{nf}}\), applies the
Pythagorean final-marginal theorem and Pinsker once, and obtains
\[
 \TVD(H_2,H_3)\leq\sqrt{q\epsilon_{\mathsf{nf}}/2}.
\]
Data processing then projects completed output/heap pairs to the returned
Boolean.
Triangle composition with the exact steps in
\Cref{eq:hybrid-chain} gives
\[
 \WinProb[H_0]
 \leq \WinProb[H_6]+\sqrt{q\epsilon_{\mathsf{nf}}/2}.
\]
Finally, the supplied IND-CPA theorem bounds \(\WinProb[H_6]\) by
\(\beta_{\mathsf{CPA}}(\cB_{\cA,q})\), proving \Cref{thm:main}.

\subsection{Why adaptivity matters}

A handwritten proof often says to replace the first \(q\) decryptions even
though an oracle adversary is a single program whose future control flow
depends on earlier oracle outputs.
In SSProve, calls are nodes inside that
program, not an external list.
The compiler makes first \(q\) semantic: run
to the next selected call, answer the call, and resume.
We have verified the correctness of our compiler;
that is, compilation neither gains nor loses behaviors.
